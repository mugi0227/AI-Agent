# デスクトップ初期設定の完了条件

対象は会社PC上のデスクトップ版。初見利用者が設定ファイルやマニュアルを開かず、設定から最初の質問まで進めることを目標とする。AWS認証・利用権限・会社の承認は利用環境で用意する前提とし、アプリが承認を代行したり認証情報を作ったりはしない。

| 完了条件 | 確認方法 |
| --- | --- |
| 未設定で起動すると、必須の設定と操作順が見える | 未設定の実Tk画面を起動する |
| 保存の同意、資料フォルダ、AI接続を画面で設定できる | フォルダ選択・設定保存を操作する |
| 保存後は再起動せず有効になる。未公開の詳細設定を保持する | 永続化・Runtimeの反映・再読込を検証する |
| 不正な値や保存失敗で元の設定を壊さず、入力を残して修正できる | 無効パス・接続先・保存エラーを検証する |
| 接続テストは明示操作でのみ実行し、業務資料を送らない | 実通信境界を模したテストで要求内容・利用上限を確認する |
| 未確認・成功・失敗を区別し、設定変更で古い成功表示を無効にする | 接続設定変更・失敗からの再試行を操作する |
| 資料0件のとき、追加方法が示される。許可フォルダ外・機密パスを取り込まない | 実ファイル選択・拒否を確認する |
| 資料の選択・添付・質問・回答・出典確認まで進める | 実Tkと模擬モデルによる一連の操作を検証する |
| 960×700以上の画面で保存・確定・取消を操作できる | 実Tkでボタンの表示領域を確認する |
| 既存の会話・継続タスク・Chrome/Edge連携を壊さない | 既存テスト、Windows/Linux・Python 3.11/3.13のCI |

実環境のBedrock接続は会社側の認証・モデル利用権限が必要。自動テストの成功と、実際の会社環境で接続済みであることは区別して報告する。初見ユーザーの利用テストは未実施であり、完了率や所要時間を測定済みとは扱わない。

## 実装・検証結果（v0.3.1 / 2026-10-21）

上記のソフトウェア上の完了条件を実装し、コア143件・実Tk操作30件で検証した。設定の初期画面、再起動なしの反映、合成入力の接続確認、資料0件からの取り込み・添付・質問・出典確認、入力修正と再試行、小画面・文字拡大時の操作を含む。
