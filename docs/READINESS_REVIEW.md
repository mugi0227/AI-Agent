# 完成度とAIへの入力方法

2026-10-16のコード確認に基づく評価。**ローカルで試せるプロトタイプとしては形になっていますが、会社で日常利用できる完成品には達していません。** 機能数だけから完成率を算出する根拠はないため、実装と動作確認を分けて評価します。

## 完成度

| 領域 | 評価 | コード上の根拠・残る確認 |
|---|---|---|
| ローカル資料の収集・検索・保存 | 基本実装あり、オフライン試験あり | `ingest.py`、`store.py`。許可フォルダ、日本語索引、重複・期限・失効。大量資料・実Office/PDFの品質は別途確認 |
| Agentの調査と候補作成 | 制御の骨組みあり、品質は未評価 | `agent.py`、`tools.py`。検索→原文、引用、承認候補、回数/予算制限をモックで試験。実モデルの回答品質は未確認 |
| 記憶・案件・通知 | 制約を含めて実装 | 承認済み記憶、案件、タスク、時間帯・集中モード・cooldown。長期試用と通知の有用性は未確認 |
| AIへの入力画面 | 最低限のデスクトップUI | `ui.py`。1行入力と送信、テキストの応答・出典。複数会話・添付・音声・送信キャンセル・生成中の文字の逐次表示はない |
| Chrome・Edge拡張 | 共通拡張とブラウザ別登録を用意 | Manifest V3、Native Messaging。Windows CIのrelay試験と実ブラウザ接続の検証は別 |
| 実Bedrock接続 | 実装あり、実接続の成功は未確認 | `bedrock.py`、`doctor.py`。SigV4/APIキー、Responses/SSEのモック試験。認証・モデル/地域・tool roundtripを実環境で確認する必要がある |
| M365 / Box / Power Automate | データ契約と構築手順 | schema、8種類のflow仕様、文字起こし用ドラフト生成器。接続済みの完成フローではない |
| 配布・常用 | 未完成 | インストーラー、署名済み配布、トレイ、OS通知、自動更新なし。Windowsスリープ復帰・長時間稼働・会社ポリシーでの確認が必要 |

自動テストが成功しても、実Bedrockや会社テナントとの疎通成功を意味しません。WindowsのCIでテスト用ファイルとCLI日本語出力の文字コード問題が見つかったため修正しました。回帰試験を含む69件のunittestと、Chrome/Edgeの登録・C#→Python通信のWindows試験があります。最新結果は[Actions](https://github.com/mugi0227/AI-Agent/actions)を確認してください。

## 指示を入力する入口

### デスクトップ

```powershell
.\.venv\Scripts\python.exe -m work_assistant gui
```

6つのタブ（会話／資料・検索／承認待ち／タスク・案件／通知／状態・設定）のうち「会話」を開きます。下部の1行入力欄に日本語で依頼し、Enterまたは「送信」で実行します。応答本文と確認した資料の出典・取得時刻が会話欄に表示されます。ユーザーの依頼は`Runtime.ask`→`Agent.turn`へ渡り、Bedrockとローカルツールで処理されます。

会話は既定の`main`セッション1つです。直近12件のメッセージを文字数上限内で使い、過去の会話は専用検索ツールで参照できます。ただし画面の再起動時に過去ログを表示し直す処理や、会話一覧・新規会話・スレッド切替はありません。入力した指示そのものを恒久的なシステム設定へ自動変換する機能もありません。

### CLI

```powershell
.\.venv\Scripts\python.exe -m work_assistant ask "案件Aの次の確認事項を、取得済み資料から整理して"
```

同じAgentへ渡し、結果はJSONで出力します。`ask`は1回の依頼を処理して終了します。対話型REPLやチャットWebサーバーではありません。GUIとCLIの並行運用を制御するプロセス間ロックはなく、単一プロセスでの利用が前提です。

### Chrome・Edge拡張

拡張を開く→文章の選択/ページ本文の取得→プレビュー・編集→ローカル保存、という資料入力です。保存後は本体の収集処理で資料として検索可能になります。拡張のテキスト欄は資料の編集欄で、AIへの指示欄ではありません。「この資料を要約して」などの依頼は本体の会話欄へ入力します。自動的に現在のタブを会話へ添付する機能はありません。

## OpenClawをどこまで参考にできているか

取り入れているのは、定期確認の実行条件、対話の優先、無通知終了、通知抑制、会話履歴と長期記憶の分離です。対応するコードと試験は[OpenClaw分析](OPENCLAW_ANALYSIS.md)にあります。OpenClawのコードの移植・依存・互換実装ではありません。

**指示入力の使い勝手は、現状では独自の簡易Tk画面に留まります。** ブラウザで使うチャット画面、複数の会話やチャネル、外部メッセンジャーからの指示、スマホ連携、プラグイン/skillの実行、LLMによる自動要約compactionは実装していません。OpenClawを参考にした運用制御はありますが、入力体験まで取り込めているとは評価できません。

## 完成へ近づける優先順

1. 実WindowsのChrome/EdgeでPing→架空資料capture→検索、実Bedrockで`doctor --live`→引用付き回答を通す。
2. 会話欄を複数行にし、履歴表示・会話切替・資料を指定して質問する導線・キャンセル/進捗表示を整える。入力の改善は現在のデスクトップUIから始められる。
3. Power Automateは情報収集ルートを1つ選んで実接続し、架空案件で1週間の通知品質・スリープ復帰・重複/失効を評価する。配布と更新の方式を決める。

常時動くWeb UIやスマホ入力を加える場合は、認証・端末からの接続範囲・常駐プロセスの設計が追加で必要です。現状のローカルアプリに画面だけ追加すれば完成するものではありません。
