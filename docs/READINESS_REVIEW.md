## 指示を入力する入口

### デスクトップ

```powershell
.\.venv\Scripts\python.exe -m work_assistant gui
```

左の会話一覧から会話を選び、中央下部の複数行入力欄へ依頼します。Enterは改行、Ctrl+Enterまたは「送信」で実行します。応答は逐次表示し、確定後は出典番号と資料名・取得時刻を表示します。ユーザーの依頼は`Runtime.ask`→`Agent.turn`へ渡り、Bedrockとローカルツールで処理されます。「資料・検索」「承認待ち」「タスク・案件」「通知」「接続・設定」も左から開けます。

会話ごとの履歴・下書き・選択資料と、最後に開いた会話を復元します。新規作成、会話名/発言の検索、名前変更、保管と復元に対応しています。直近12件のメッセージを文字数上限内でモデルへ渡し、過去の会話は専用検索ツールで参照できます。入力した指示そのものを恒久的なシステム設定へ自動変換する機能はありません。詳しくは[会話UXの使い方](CHAT_UX.md)を参照してください。

### CLI

```powershell
.\.venv\Scripts\python.exe -m work_assistant ask "案件Aの次の確認事項を、取得済み資料から整理して"
```

同じAgentへ渡し、結果はJSONで出力します。`ask`は1回の依頼を処理して終了します。対話型REPLやチャットWebサーバーではありません。GUIとCLIの並行運用を制御するプロセス間ロックはなく、単一プロセスでの利用が前提です。

### Chrome・Edge拡張

拡張を開く→文章の選択/ページ本文の取得→プレビュー・編集→ローカル保存、という資料入力です。本体の取り込み後、会話の「資料を添える」でその資料を選び、「この資料を要約して」と依頼できます。拡張のテキスト欄は資料の編集欄です。自動的に現在のタブを会話へ添付する機能はありません。

## OpenClawをどこまで参考にできているか

取り入れているのは、定期確認の実行条件、対話の優先、無通知終了、通知抑制、会話履歴と長期記憶の分離です。対応するコードと試験は[OpenClaw分析](OPENCLAW_ANALYSIS.md)にあります。OpenClawのコードの移植・依存・互換実装ではありません。

v0.2.0では、会話一覧・下書き復元・複数行入力・資料選択・逐次表示・停止・再実行を、OpenClawの操作設計を参考に独立実装しました。参照ソースと対応は[会話UX](CHAT_UX.md)に記載しています。ブラウザで使うチャット画面、外部チャネル、スマホ、プラグイン/skill、LLMによる自動要約compactionは未実装です。OpenClaw全体との機能互換を意味しません。

## 完成へ近づける優先順

1. 実WindowsのChrome/EdgeでPing→架空資料capture→検索、実Bedrockで`doctor --live`→引用付き回答を通す。
2. 会社PCで日本語IME、高DPI、実Bedrockの逐次表示/停止、資料選択と回答品質を試用する。設定フォーム化、より長い履歴の表示や運用上の改善を検討する。
3. Power Automateは情報収集ルートを1つ選んで実接続し、架空案件で1週間の通知品質・スリープ復帰・重複/失効を評価する。配布と更新の方式を決める。

常時動くWeb UIやスマホ入力を加える場合は、認証・端末からの接続範囲・常駐プロセスの設計が追加で必要です。現状のローカルアプリに画面だけ追加すれば完成するものではありません。
