## 入力と操作

```powershell
python -m work_assistant gui
```

通常の依頼は会話の複数行入力欄から、Ctrl+Enterまたは「送信」で実行します。Enterは改行です。待機・再開を含む依頼は「継続タスクに登録」を使い、「実行管理」で状態と成果物を確認します。「資料を添える」で最大6件の取得済み資料を指定できます。

会話の履歴・下書き・選択資料と最後に開いた会話を復元します。直近12件に加え、条件を満たす長い会話は要約を利用し、原文の会話履歴も検索できます。入力を自動的に恒久的なシステム設定へ変換することはありません。

CLIも同じ実行基盤を使います。

```powershell
python -m work_assistant ask "取得済み資料から確認事項を整理して"
python -m work_assistant work add "会議資料を準備し、追加情報を待って再確認する"
python -m work_assistant work list
python -m work_assistant work metrics
```

単発の`ask`、継続タスクの`work`、役割の`role`、保存した記憶の`memory`、定期実行の`routine`を用意しています。同じ保存先のプロセス間でもDBで実行権を管理します。共有ネットワークドライブ、複数OSユーザーのサーバー運用は対象外です。

操作方法は[会話UX](CHAT_UX.md)と[継続タスクの使い方](DURABLE_WORK.md)を参照してください。

## OpenClawとの対応

会話UIは以前確認した固定コミットを参照し、v0.3.0の実行・記憶・要約の設計では2026-10-21の固定コミットを確認しました。参照した具体的なファイルと判断根拠は[アーキテクチャ評価](ARCHITECTURE_REVIEW.md)にあります。独立実装であり、OpenClaw本体への依存はありません。

対象は継続的な仕事を扱うための主要な構造です。外部チャネル、公開Web Gateway、任意のShell/PC操作、画面を観察して手順を学習する機構、複数ユーザーに対する強制隔離を含む製品全体の互換実装ではありません。保存した状態は復元できますが、PCが停止・スリープしている間には動きません。

## 実環境での確認

実WindowsのChrome/EdgeでPing→架空資料capture→検索、実Bedrockで`doctor --live`→引用付き回答を確認します。その後、架空の継続タスクで追加取得待ち・再起動・取消・要約・役割分担を検証し、少量の許可された資料で検索適合率と不要提案率を記録します。自動テストに通ったことを、これらの実環境評価の代わりにはしません。
